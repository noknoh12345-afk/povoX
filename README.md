# povoX

povo2.0 のデータ残量を見守り、足りなくなりそうなら **手持ちのコードを入れる・使い放題やデータ追加を買う** iPhone アプリ(非公式)。何をするかは **ルール(JavaScript)** で決め、実行は必ず安全装置を通ります。

- 残量・減り方の予測(「このペースであと何時間」)・3日分のグラフ、ホーム/ロック画面のウィジェット
- ルールは「何をするか」を返すだけ。**既定は「通知で確認」**: ロック画面の「実行する」を押したときだけ購入・適用
- **レシピ 266 個**: 書かずに「選ぶだけ」で使えるプリセット(残量ライン/なくなる前に/夜は買わない/電池を節約/Wi-Fiが切れたら/時間帯/使い放題の見張り/使いすぎ/知らせるだけ)。選ぶ前に下見できる
- **シミュレーター**: 残量・電池・Wi-Fi・使い放題中などを仮に動かして、ルールと安全装置の判断を確かめる(povo に通信しない)
- テンプレート5種(標準 / コードだけ / なくなる前に足す / 夜は買わない / 知らせるだけ)と、自由に書けるルール
- コードの一括登録とカメラ読み取り、ショートカット(自動チェック・残量・購入のしかたの切り替え)
- **位置情報での起動**(「常に許可」で、移動・立ち寄りを合図に残量チェック。無料 Apple ID でも可)
- **アカウントの閲覧**: プロフィール・請求(PDF)・友だち紹介コード、通信設定への近道
- **Mac(PlayCover など)・LiveContainer 対応**: 使えない機能は自動で隠す。Mac はキーボードで操作(⌘1〜5 でタブ、⌘R 更新、⌘Return でチェック)

KDDI・povo・Circles.life とは無関係です。povo への通信は povo-web と同じ公開ライブラリ [uirooong/povo-core](https://github.com/uirooong/povo-core)(MIT)を使い、送る値は povo-android と同じです。設計は [docs/DESIGN.md](docs/DESIGN.md)。

## 入れ方(Mac から)

1. **Releases** から `povoX.ipa` をダウンロード(ウィジェットが使えなかったら `povoX-nowidget.ipa`)。
2. Mac の [Sideloadly](https://sideloadly.io/) に ipa をドラッグし、自分の Apple ID で「Start」。
3. iPhone で
   - 設定 → 一般 → VPNとデバイス管理 → 自分の Apple ID を「信頼」
   - 設定 → プライバシーとセキュリティ → **デベロッパモード** をオン
   - 設定 → 一般 → **Appのバックグラウンド更新** で povoX をオン

無料の Apple ID だと7日ごとに入れ直しが要ります(データとログインは残ります)。無料 Apple ID では VPN／ネットワーク拡張の署名ができないため、「ほかのアプリの通信を止める」機能は使えません(設定アプリでの手動のオフと、残量が少ないとき知らせるレシピで代替します)。

### Mac(PlayCover など)・LiveContainer

- **Mac**: PlayCover などで iPhone 版をそのまま動かせます。キーボードで操作できます(⌘1〜5 でタブ、⌘R で更新、⌘Return で今すぐチェック)。バックグラウンド更新と位置情報での起動は Mac では動かないので、アプリを開いている間の自動チェックを使ってください。
- **LiveContainer**: `povoX-nowidget.ipa` を使ってください。ウィジェットとバックグラウンド更新は LiveContainer の仕組み上動きません。アプリを開いている間の自動チェックとショートカットを使ってください。これらは自動で見分けて、使えない機能は隠します。

## 最初にやること

1. 初回の案内で通知を許可する(確認の通知に必要)。
2. まず **モック**(認証コード `000000`)で一通り触る。モックは購入・コードで残量や「使い放題中」が実際に変わる作り物の回線です。
3. 本番でログインし、残量・ご利用中のトッピングが公式アプリと一致するか見る。
4. 「コード」に手持ちのコードを登録(1行に `コード タグ メモ`、カメラでも読める)。
5. 「ルール」→ テンプレートを選び、**シミュレーター** で判断を確かめる。
6. 「設定」で月の上限・1日の回数を決める。慣れたら購入やコードを「自動」にしてもよい。
7. ショートカットのオートメーションを登録する(下)。

## 「常に取得」のしくみ

iOS はアプリを常に動かせないので、起こされる機会を組み合わせます。

| きっかけ | 確実さ | 備考 |
| --- | --- | --- |
| ショートカットのオートメーション | ◎ | バッテリー20%未満・充電器を外した・Wi-Fi 切断・時刻・App を開いた など。「すぐに実行」で確認なし |
| 位置情報(常に許可) | ○ | 移動・立ち寄りを合図に起動(ctx.trigger は location / location-arrive / location-leave)。Mac・LiveContainer では無効 |
| バックグラウンド更新 | △ | iOS が決める。間隔は残量の減り方で自動調整(なくなりそうなら短く、使い放題中は終わる頃に)。Mac・LiveContainer では無効 |
| アプリを開いている間 | ○ | 同じ間隔で自動チェック |
| 通知の「実行する」 | ◎ | 確認待ちをロック画面から実行 |

ショートカット App → オートメーション →「+」→ きっかけ →「すぐに実行」→ アクション **「povoXの自動チェック」**。「きっかけ」に入れた文字はルールの `ctx.trigger` に入ります。

## ルール

```js
function decide(ctx) {
  const d = ctx.data;
  if (ctx.network === "wifi") return skip("Wi-Fi なので何もしない");
  if (d.unlimited.active || d.leftGB >= 0.5) return skip("十分");
  const short = ctx.battery.level <= 20 && !ctx.battery.charging;   // 電池が少ないなら1時間だけ
  return firstOf(
    applyCode(),                                                     // 手持ちのコード
    buy(cheapest(ctx.catalog(), p => p.unlimited && p.hours === (short ? 1 : 24))),
    notify("povo 残りわずか", `${d.leftMB.toFixed(0)}MB`)
  );
}
```

使えるもの: `skip` `notify` `applyCode` `buy` `firstOf` `all` `cheapest` `log` `state`、`ctx.data`(残量・使い放題・トッピング)`ctx.forecast`(あと何時間)`ctx.codes` `ctx.budget` `ctx.battery` `ctx.network` `ctx.now` `ctx.trigger` `ctx.catalog()`。詳しくはアプリの「ルールの書き方」。

## 安全装置(ルールからは外せません)

- 購入・コードは設定の **しない / 通知で確認 / 自動** に従う。試運転は記録だけ。
- 購入: 月の上限金額・1日の回数・前回からの間隔・3Dセキュアが要る商品は買わない・同じ商品は2分あける。
- コード: 送ったら二度と自動では送らない・15秒に1回・使い放題中(または分からないとき)は送らない。
- 1回の自動チェックで使う購入・コードは1つまで。確認待ちは既定30分で期限切れ。実行直前にもう一度チェック。
- povo-web と同じ: 通信は1本ずつ・自動リトライなし・403 で全部停止(「通信を再開」まで)・待機時刻を守る・トークン更新は期限切れ後だけ。通信は5分間に20回まで。
- ルールの実行は3秒まで。

## 検証について

CI(GitHub Actions)で毎回、iOS シミュレータに本物のアプリを入れて次を回し、スクリーンショットを `ci-artifacts` ブランチと Actions の成果物に残しています(povo にはモックで、通信しません)。

- 単体テスト 16本: JavaScriptCore でのルール評価(テンプレート全部・エラーの行番号・無限ループを3秒で止める)、エンジンの型付き API、確認待ち → 実行、停止の保存、キーチェーン、ウィジェット用の共有ファイル、ショートカットの3つのアクション
- 画面テスト 5本: 初回案内 → ログイン → 自動チェック(確認待ち)→ 実行 → 履歴 / ルール・シミュレーター・テンプレート・エディタ / コード・トッピング・設定・ウィジェット / ダークモード / **通知の「実行する」**(バナーを長押し → 実行 → 使い放題中になる → 「購入しました」の通知)
- IPA の検査: 中の実行ファイルが読み込むライブラリを全部調べ、iOS のものとアプリの中のもの以外があれば公開しない(`tools/check-macho.py`)
- リリース構成での起動: 実機に入れるのと同じリリース構成のシミュレータ版を、ビルドに使ったファイルを隠した状態・テスト用の起動オプションなしで起動し、落ちないことを確かめる

この検証で、通知の「実行する」を押すとアプリが落ちる不具合を見つけて直しています(システムの完了ハンドラを画面以外のスレッドから呼んでいた)。

**build-9・build-10 は実機で起動した瞬間に落ちます。** Rust のエンジンを、ビルドした Mac 上のファイル(.dylib)として読み込む作りになっていました。シミュレータはその Mac の上で動くので気づけませんでした。0.2.1 からはエンジンをアプリ本体に組み込み、上の2つの検査で同じ種類の誤りを公開前に止めます。入れ直したら、アプリの「設定」の一番下の「バージョン」が 0.2.1 以上になっているか確かめてください。

シミュレータでは確かめられないこと(本物の povo への通信、バックグラウンド更新の起こされ方、ロック画面での Face ID、署名ツールでの App Group)は、下の順で確かめてください。

1. 本番ログイン → 残量・トッピングが公式アプリと一致
2. コード1件を手動で適用(コード適用は povo-web と同じく実アカウント未検証)
3. 購入は「通知で確認」のまま、最安のもの1回で通知 →「実行する」
4. ウィジェットを置いて残量が出るか(出なければ `povoX-nowidget.ipa` でも可)
5. ショートカットのオートメーションで自動チェックが動くか(履歴に残る)

## 構成

```
core/                Rust のエンジン(povo-core を利用)。UniFFI で Swift に型付きの API
  src/plan.rs        ルールの計画の実行(安全装置・確認待ち・試運転・シミュレーション)
  src/engine.rs      ログイン・残量・購入・コード・設定
  src/history.rs     履歴と予測 / rulectx.rs ルールに渡す材料 / state.rs 保存
  src/backend.rs parse.rs protocol.rs   povo-web から流用 / mock.rs 状態つきモック
ios/                 SwiftUI アプリ(XcodeGen)・ウィジェット・単体テスト・画面テスト
  PovoX/Resources/   rule-prelude.js(ルールの下ごしらえ)と templates/
tools/rule-harness.js  ルールをパソコン上でエンジン(モック)につないで試す
docs/DESIGN.md       設計
```

開発:

```sh
cd core && cargo test                              # エンジン(モック)
cargo build --example cli
node tools/rule-harness.js --dir /tmp/st --scenario low --ctx '{"battery":{"level":10}}'
```
