# povoX 独自機能の計画(v4)

公式アプリ(povo2.0 / Selfcare-Japan 1.69.0)には無い、povoX ならではの機能を増やす計画。
「レシピ(ルールのプリセット)」ではなく、**アプリの機能そのもの**を足す。

数より中身を優先する。文字どおり数百個の“全部ユニークな機能”は現実的でないため、
**公式では作れない、尖った機能**を小さく作って 1 つずつ CI に通して出す。

## 方針の更新(ユーザー指示 2026-10-15)

- **新機能はアプリ内だけで作る。** 新しい外部サーフェス(Live Activity・新規ウィジェット・コントロールセンター等)は**保留**にする。
- **既存のウィジェットと、実装済みの機能は消さずにそのまま残す**(`PovoXWidget` は現状維持)。
- 中身は「アプリ内で賢くする系」を優先する。優先順: **①料金最適化 → ②バックテスト → ③目標ドリブン**。
- 下の B(通知・表示)の新規ぶんは、この方針により**保留**(記載は残す)。A・C・D と、下の「A+. 賢い自動操縦」を進める。

## v4: 内蔵ショートカットと「今日のプラン」(ユーザー指示 2026-10-16)

- 「最安」は軸から外す(料金最適化はショップの中に残す)。軸は **考えなくていい・先回り**。
- **オートメーション(内蔵のショートカット)**: いつ / もし / すること をタップで組む。ボタン(ホームのタイル)・予定・時刻・残量・Wi-Fi・電池・位置・ショートカット App・予約。ギャラリー22種、最初から7つ。Siri/ショートカット App から実行(AppEntity)。
  - povo への操作はエンジンの安全装置を必ず通る。計画の `confirm`(true=必ず確認 / false=その場で押した実行=`flow:` のきっかけだけ確認済み)をエンジンに追加。
  - 時刻・予定はローカル通知で予約(無料 Apple ID ではアプリを決まった時刻に起こせない)。「実行する」ボタン付き。
- **今日のプラン**: カレンダーから外出を拾い、必要量を見積もり、足りなければ出かける前に何を入れておくか(予約 / 今すぐ)。前の晩に明日のプランを通知。
- 評価・見積もり・ギャラリーは Foundation だけ(`tools/flow-check.sh` で iOS なしに検査、CI でも実行)。

## A+. 賢い自動操縦(アプリ内。最優先)

povoX の核は「お金を預けて自動で回す」こと。信頼して任せられるよう、アプリ内で賢く・透明にする。

| ID | 機能 | 何をする | 仕組み(データ) | 規模 |
|---|---|---|---|---|
| S1 | 料金最適化(組み合わせ最安) | 予測した必要量を、最小の金額でまかなう買い方(コード→データ→使い放題の最安の組み合わせ)を提示 | `snapshot`＋`insights`(予測)＋`catalog`(¥/GB・¥/時)＋`codes`＋`budget` | M |
| S2 | バックテスト(自分の履歴で検証) | 「このルールなら先月どうだったか」を記録に対して走らせ、浮いた¥・ゼロ回避回数を出す | `history`＋ルールエンジン＋`simulate` | M/L |
| S3 | 目標ドリブン(命令でなくゴール) | 「月¥Xまで・ゼロにしない」から方針(ルール)を自動生成 | S1 の最適化＋設定 | L |
| S4 | 先読みプレビュー(この先7日で何をするか) | 今のルール＋予測で、将来の購入・支出を実行前に見せる | `insights`＋ルール評価の反復 | M |
| S5 | なぜやった/なぜやらなかった | 各判断に反実仮想(上限で抑えた等)を添える | 既存の `RunRecord`＋安全装置の判定理由 | S/M |
| S6 | 急減検知(= A4) | 普段より速い減りを検知して知らせる | 直近の減り vs 7日平均 | M |

## 前提と制約(正直に)

- 通信は公開ライブラリ [povo-core](https://github.com/uirooong/povo-core) 経由のみ。お金が動く操作は従来の安全装置(上限・回数・間隔・3DS 除外・確認)を必ず通す。
- 無料 Apple ID でサイドロードするため、**VPN／ネットワーク拡張・プッシュ通知は使えない**。よって「他アプリの通信遮断」や「サーバープッシュ更新」は作らない。ローカル通知・ウィジェット・Live Activity・位置情報は使える。
- **Mac(PlayCover)・LiveContainer** では拡張(ウィジェット・Live Activity)が動かない。`Runtime` で見分けて、使えない機能は隠す。これらの機能は実機 iPhone 向け。
- データ源は既にエンジンにあるものを最大活用: `snapshot`/`history`(14日)/`insights`(減り方・あと何時間・今日/7日の使用)/`budget`/`catalog`/`purchase_history`/`bills`/`referral`/`account_profile`。

## 作る順番(波)

小さく価値が高いものから。各波の最後に必ず CI(単体＋画面テスト＋IPA 検査＋リリース起動)を通す。

- **Wave 4**: A3・A6・C1・B4(主に Swift。見てすぐ分かる価値)
- **Wave 5**: A1・A2・C2(エンジンにヒートマップ等を追加)
- **Wave 6**: A4・A5・D3(エンジンに「ペース警戒」「使い放題エピソード記録」)
- **Wave 7**: B2・B3(ウィジェットの拡充)
- **Wave 8**: D1・D2(モード切替・スケジュール、App Intent)
- **Wave 9**: B1・C3(Live Activity と請求一括。いちばん大きいので最後)

## 横断的な方針

- **エンジン追加**は必ず mock とテストをセットで。`cargo test` が通ってから Swift へ。
- **環境ガード**: Live Activity・ウィジェット系は `Runtime.widgetsAvailable` 等で Mac/LiveContainer では無効化・非表示。
- **テスト**: エンジンは `core/src/tests.rs`、Swift は `PovoXTests`(ロジック)と `PovoXUITests`(画面・スクショ)。新機能ごとに 1 画面はスクショを残す。
- **CI**: 既存の build.yml をそのまま使う(IPA の Mach-O 検査・リリース構成での起動確認つき)。
- **バージョン**: 波ごとに `CURRENT_PROJECT_VERSION` を上げ、節目で `MARKETING_VERSION` を上げる。
