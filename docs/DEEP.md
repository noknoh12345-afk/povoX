# 予定から先回りする機能を「深く・正しく」作る(コスパ最強)

v0.3.0 で広げた「今日のプラン」とオートメーションを、**機能を増やさずに**正しくする計画と、その進み具合。
各段の終わりで止め、数字と未検証のことを報告する。

## 目的: コスパ最強の定義(数字で判定する)

**外出中に切れない、を守ったうえで、1か月に povo に払う額を最小にする。** 安さだけ・安心だけのどちらでもない。

| 指標 | 定義 | 材料(生データ) |
|---|---|---|
| 切れ(制約・目標0) | 外出の時間(予定の開始〜終了、移動の前後を含む)に、残量 50MB 未満かつ使い放題でない状態があった回数と分数 | 残量の記録 + 予定 |
| 支払い | その月に povo に払った額(ルール・オートメーション・手動の全部) | 購入台帳 + povo 公式の購入履歴 |
| 無駄 | ① 使い放題の価格が、その期間に実際に使ったモバイル通信量を一番安いデータ追加でまかなう価格より高かった差額 ② データ追加・コードで増やした分が期限までに使われずに残った分(換算額) | 通信量カウンタ(使い放題中も測れる)+ トッピング一覧 + 残量の記録 |
| 1円あたり | 外で使ったモバイル通信量 ÷ 支払い | 通信量カウンタ + 支払い |
| 手間 | 1日の通知の数・「実行する」を押した回数 | 計測の記録 + 実行の記録 |

- povo の残量は **使い放題中は減らない**。使い放題の元が取れたかは povo の数字では測れないので、
  端末の通信量カウンタ(getifaddrs の pdp_ip* / en*)を、povo とは独立した物差しとして記録する。
- 上限の値(無駄は月いくらまで・通知は1日何件まで)は、第3段の前に利用者が決める。

## 材料(第0段)— 済

- エンジンの書き出し `PovoEngine.exportJson(includePurchases:)`: 残量の記録(**120日・2万件まで残すよう延長**)、
  実行の記録、購入台帳、確認待ち、コード(伏せ字)、設定、予算、予測、手元の残量、トッピング一覧、ログ、povo 公式の購入履歴。
  ログイン情報とコードの全文は入れない(テストで確認)。
- 予定の生の項目(過去90日・先2日): タイトル・場所・場所の座標・空き時間・状態・自分の参加ステータス・繰り返し・
  カレンダーの種類・メモの「#タグ」(本文は出さない)。「伏せる」にすると文字は短い記号に置き換える。
- 設定 → 計測と書き出し → 「書き出すファイルを作る」で1つの JSON にし、共有シートで渡す(端末の外へ自動では送らない)。
- **未入手**: povo 公式の「日ごとの利用量」(povo-core に該当する API が見つかっていない)。iOS の設定のアプリ別通信量はアプリから読めない(必要ならスクリーンショット)。

## 第1段: 前提の測定 — 記録の仕組みは済・実機の1週間はこれから

記録するもの(端末の中と os_log `jp.povox.app / wake`):

- `bg-launch`: バックグラウンド更新で起こされた時刻と、頼んだ時刻(earliestBeginDate)。`bg-expired`: 時間切れ。
- `run`: 自動チェックの時刻ときっかけ(バックグラウンド・アプリ表示中・ショートカット・位置情報・オートメーション)。
- `notif-scheduled` / `notif-cancelled` / `notif-delivered`: 予約した通知・入れ直しで外れた通知・届いた時刻(通知センターから)。
- すべての記録に通信量カウンタ(モバイル・Wi-Fi・端末の起動時刻)を付ける。

集計(設定 → 計測と書き出し に表示・書き出しにも入る): 1日の回数・きっかけ別、間隔の中央/90%/最長、
昼(7〜23時)に3時間以上あいた回数、昼の1時間ごとの網羅率、バックグラウンド更新の遅れ、通知の遅れ、日ごとのモバイル通信量。
集計の計算は `tools/flow-check.sh`(iOS なし・CI でも)と単体テストで検査している。

報告に要るもの: **実機で1週間使ったあとの、この画面の数字(または書き出したファイル)**。

## 学習(第2段の仕組み)— 作り物のデータで検査済み・実データはこれから

端末の中だけで、次を覚える(アプリを開くたび・30分に1回まで。「学習」画面から今すぐも可):

- **予定の種類ごとの1時間あたりの量**(移動の前後30分を含む・90%): 過去90日の外出の予定の時間に、実際に使った量から。
  使用量の物差しは通信量カウンタ(povo の数え方に換算)、無ければ povo の残量の減り。件数が少ないうちは最初の目安に寄せる(2件ぶんの重み)。
- **いつもの1日**: 平日/休日(土日祝)× 時間ごとのモバイル通信の中央と90%。
- **povo の数え方 ÷ 端末のカウンタ** の比。
- **利用者の直し**: 今日のプランの予定を「家だった」「外出だった」と直すと、同じ名前の予定(回の数字は無視)にも効く。
- **確かめ**: 古い 2/3 で覚え、新しい 1/3 の予定で「最初の目安」と「学習後」の誤差・90%を超えた割合・ピンボール損失を比べる。

学習した量があれば今日のプランはそれを使い(「学習済み」と表示)、なければ最初の目安 × 使い方の濃さ。

作り物のデータ(ライブは本当は 1時間 約400MB、会議は 20MB、povo の数え方はカウンタの1.1倍、60日)での検査:
ライブの量が実際の値の近くに収まり、povo との比 1.1 を当て、学習に使っていない予定で学習後のほうが外れにくいこと
(`tools/flow-check.sh` の LearnChecks)。**実データでの数字はまだ無い。**

## 目覚まし時計のようなスケジュール

自動化タブ →「スケジュール」。時刻のホイール・繰り返し(毎日 / 平日=土日祝を除く / 休日 / 曜日 / 1回)・祝日は鳴らさない・
どんな日に(外出の予定がある日だけ / ない日だけ / 今日の予定に足りない日だけ)・ラベル・鳴ったらすること・スヌーズ(押すか消すまで)。
日本の祝日は計算で出す(振替休日・国民の休日・2019〜2021年の特例を含む。2026年の全18日を検査)。
時刻だけで決まるものは8日先まで前もって通知を予約し、残量や予定で中身が変わるものは36時間先まで中身を作り、
その先は「鳴ること」だけを予約する(アプリが起こされなくても時刻には鳴る)。
